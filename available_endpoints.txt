=====================================================
AUTHENTICATION  (2FA / OTP FLOW)
=====================================================

Primary flow
------------
POST    /auth/register              - Sign-up + email OTP dispatch
                                      Body: { "email", "password" }
                                      Returns: { challenge_token, masked_destination,
                                                 expires_in, otp_required: true }
                                      Errors: 409 if email already registered
                                      Follow up with POST /auth/verify-otp

POST    /auth/login                 - Step 1 - validate credentials + email OTP
                                      Body: { "email", "password" }
                                      Returns: same shape as /auth/register

POST    /auth/login-email           - Step 1 - passwordless (OTP only)
                                      Body: { "email" }
                                      Anti-enumeration: identical response whether email exists or not

POST    /auth/verify-otp            - Step 2 - exchange OTP for JWT
                                      Body: { "challenge_token", "otp" }
                                      Returns: { access_token, token_type, expires_in }

POST    /auth/resend-otp            - Re-send OTP (subject to cooldown)
                                      Body: { "challenge_token" }

Frontend-compatible aliases (demo / simplified)
------------------------------------------------
POST    /api/auth/login             - Simplified login alias (demo mode)
POST    /api/auth/register          - Simplified register alias (demo mode)
GET     /api/auth/me                - Current user info (no auth required)

Security notes:
  - OTP hashed (SHA-256 + pepper) before storage; plaintext only sent by email
  - Challenge token hashed before storage
  - OTP expires in OTP_EXPIRE_MINUTES (default 5 min)
  - Max OTP_MAX_ATTEMPTS (default 5) per OTP before lock
  - Login rate limit: OTP_LOGIN_RATE_LIMIT_PER_HOUR per (email, IP)
  - Verify rate limit: OTP_VERIFY_RATE_LIMIT_PER_MINUTE per IP
  - Resend cooldown: OTP_RESEND_COOLDOWN_SECONDS (default 30 s)

COMPLETE DRUM PROCESSING WORKFLOW
=====================================================

WORKFLOW 1: BASIC  (demo - no auth)
=====================================
1. POST /api/videos/upload
2. POST /api/videos/analyze/{video_id}
3. POST /notation/                               Body: { "video_id": "demo-video-{ts}" }

WORKFLOW 2: ENHANCED  (demo - no auth)
========================================
1. POST /api/videos/upload
2. POST /api/videos/{video_id}/extract-audio
3. POST /api/videos/{video_id}/separate-sources?method=spectral&save_sources=true
4. POST /api/videos/{video_id}/enhance-drums?drum_type=all&enhancement_strength=0.4
5. POST /api/videos/analyze/{video_id}
6. POST /notation/                               Body: { "video_id": "demo-video-{ts}" }

WORKFLOW 3: PRODUCTION  (auth required, real DB)
=================================================
1. POST /auth/login  ->  POST /auth/verify-otp  ->  JWT
2. POST /videos/upload
3. POST /videos/{uuid}/extract-audio
4. POST /audio/separate-sources/{uuid}
5. POST /audio/enhance-drums/{uuid}
6. POST /audio/analyze/{uuid}
7. POST /notation/                               Body: { "video_id": "{uuid}" }

=====================================================
FRONTEND INTEGRATION  (JavaScript / TypeScript)
=====================================================

// Demo workflow - no auth required
async function demoWorkflow(videoFile) {
  const fd = new FormData();
  fd.append('file', videoFile);

  const { id } = await fetch('/api/videos/upload', { method: 'POST', body: fd })
    .then(r => r.json());

  await fetch(`/api/videos/${id}/extract-audio`, { method: 'POST' });
  await fetch(`/api/videos/analyze/${id}`, { method: 'POST' });

  const notation = await fetch('/notation/', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ video_id: id, time_signature: '4/4' }),
  }).then(r => r.json());

  return notation; // { id, video_id, tempo, notation_json, demo_mode: true }
}

=====================================================
AUDIO PROCESSING PARAMETERS
=====================================================

Source Separation Methods:
  spectral (default/recommended) - fast spectral masking
  nmf                            - Non-negative Matrix Factorization
  ica                            - Independent Component Analysis (stereo only)

Enhancement drum_type values:
  kick | snare | hihat | cymbals | toms | all

Stem export formats:   wav | flac | aiff
Stem bit depths:       16 | 24 | 32

Supported video input:  .mp4  .avi  .mov  .mkv  .webm
Supported audio input:  .wav  .mp3  .flac  .m4a  .ogg

KNOWN DEMO-MODE BEHAVIOURS  (non-UUID video IDs)
=====================================================

  GET  /videos/{demo-video-{ts}}          -> demo JSON (no DB, no auth check on non-UUIDs)
  GET  /api/videos/{demo-video-{ts}}      -> demo JSON (no auth)
  POST /api/videos/analyze/{id}           -> always returns demo analysis JSON
                                             (file_found: true if file exists on disk)

  POST /notation/                         -> demo notation JSON when video_id is not a UUID
  GET  /notation/                         -> empty list when token is absent or expired
